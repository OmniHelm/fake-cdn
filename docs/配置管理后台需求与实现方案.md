# 配置管理后台需求与实现方案

## 1. 建设目标

将 `config.json` 中影响流量生成的主要配置迁移到 CDN Panel 后台管理，减少人工
修改 JSON 引起的格式错误、权重错误和误推送风险，同时保持 CLI 与生成器继续以
`config.json` 为单一事实来源。

本期不在后台直接启动生成、补推或真实推送任务。保存配置和执行任务保持解耦。

## 2. 用户与权限

- 管理员：查看、编辑、校验和保存配置，查看配置审计记录。
- 只读人员：本期沿用 Dashboard 统一登录，不单独拆分只读角色。
- 未启用 Dashboard 认证时仍可本地使用；对外开放时必须配置用户名、密码和稳定的
  Session Secret。

## 3. 功能范围

### 3.1 六步配置向导

1. 基础信息
   - 配置名称
   - 部署平台
   - 租户 ID
   - 项目
2. 流量目标
   - 总流量数值、单位和计量进制
   - 默认业务画像
   - 随机种子
3. 时间窗口
   - 开始时间、结束时间
   - 时区
   - 生成间隔
4. 域名与地区
   - 域名、权重、业务画像的表格编辑和删除
   - 搜索、CSV 导入、批量粘贴、添加域名、平均分配权重
   - 国家代码、地区标识和地区权重编辑
   - 域名/地区权重实时校验
5. 真实性参数
   - 星期倍率
   - 日级和时间片噪声
   - 月初月末增益
   - 缓存命中率、对象大小、回源失败率范围
   - 异常概率
6. 校验发布
   - 目标流量、时间点数、预计记录数和等效平均带宽预览
   - 预览/推送配置模式
   - Dry-Run、本地保存和输出目录

### 3.2 审计日志

- 保存时间
- 操作者
- 保存动作
- 旧 revision 和新 revision
- 旧配置备份位置

### 3.3 响应式要求

- 桌面端保持侧栏、步骤条、主编辑区和校验摘要并列。
- 中等宽度隐藏步骤文字和右侧摘要，保留核心编辑能力。
- 移动端隐藏侧栏，工具按钮收敛为图标，表格横向滚动，底部保存操作保持可达。

## 4. 校验规则

- 使用 `normalize_config` 作为最终业务校验入口，避免后台和 CLI 规则分叉。
- 开始/结束时间必须存在、按时间粒度对齐，且结束时间不早于开始时间。
- 至少一个域名和一个地区。
- 域名格式合法且不重复，最多 1000 个。
- 地区最多 200 个。
- 后台编辑态的域名权重与地区权重必须分别合计为 100%。
- 预览模式强制启用 Dry-Run。
- 业务画像只能选择生成器支持的画像。

## 5. 保存与一致性方案

```text
[Dash 配置向导]
        │
        ▼
[编辑态校验与预估]
        │
        ▼
[ConfigManager.validate]
        │
        ├── revision 不一致 ──> 409 语义冲突提示
        │
        ├── 备份旧 config.json
        │
        ├── 同目录写临时文件 + fsync
        │
        ├── os.replace 原子替换
        │
        └── 追加 audit.jsonl
```

- revision 使用原配置文件字节的 SHA-256。
- 用户打开页面时记录 revision，保存时进行乐观并发检查。
- 备份保存在 `output/config-management/backups/`。
- 保存失败时不替换原配置；配置校验失败时不产生备份。
- 审计写入失败不会回滚已成功的配置保存，但会在页面显示警告。

## 6. 代码结构

- `fake_cdn/core/config_manager.py`
  - 配置读取、标准化、管理规则校验、统计预估、revision、备份、原子保存、审计。
- `fake_cdn/dashboard/config_page.py`
  - 六步配置页面、表格操作、实时预估、保存回调和审计页面。
- `fake_cdn/dashboard/assets/config.css`
  - 选定原型对应的桌面与响应式样式。
- `fake_cdn/dashboard/app.py`
  - 注册 `/config`、`/config-audit` 路由和导航入口。
- `tests/test_config_manager.py`
  - 覆盖旧配置兼容、无副作用读取、原子保存、备份审计、并发冲突和非法域名。

## 7. 安全边界

- 后台保存不会自动执行 simulation、realtime、catchup 或 HTTP 推送。
- API Endpoint 和 VIP 继续优先通过环境变量提供，后台不展示环境变量中的敏感值。
- 推送配置仍受 CLI 的 Endpoint/VIP 检查与交互确认保护。
- Dashboard 的现有认证中间件同时保护配置管理和审计页面。

## 8. 验收标准

- 六个步骤均可访问，核心输入可编辑且页面切换不丢失数据。
- 域名搜索、添加、删除、CSV 导入、批量粘贴和平均权重可用。
- 非 100% 权重、重复域名、非法时间窗口等配置无法保存，并显示明确原因。
- 合法配置可保存，旧版本备份和审计记录可查。
- 外部修改配置后，旧页面保存会被 revision 冲突阻止。
- 保存配置不触发生成或网络推送。
- 单元测试、静态检查和浏览器主流程验证通过。
